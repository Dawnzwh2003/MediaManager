## 发现与修复

根目录已采用 Cargo workspace，但 Vite 原有 watch.ignored 只排除 src-tauri、.tools 和 archive，未排除根目录 target。并行原生编译时，开发服务器日志出现 target 内 exe/pdb/dll 等文件的 EBUSY 监听错误，以及 target 内生成 HTML 导致的 page reload。

修复：在 vite.config.ts 增加 `**/target/**` 忽略规则，保持其他监听行为。新增独立 `test:dev` 脚本及 tests/development/vite-watch.test.mjs，启动实际 Vite 服务并验证 Cargo 输出目录不进入监听集合、源码变化仍产生事件、target 内合成文件变化不产生事件。临时目录在关闭服务器后清理。

回归实验：暂时移除 target 忽略规则，测试在 `Cargo output directory must not be watched` 断言失败；恢复规则后 1/1 通过。测试最初的搭建尝试未启动 Vite listen，收不到源码事件；补齐真实 server.listen 后，采用默认原生监听即可通过，无需修改应用监听模式。前端常规测试、类型检查、生产构建和 Tauri release 构建已在最终配置上通过。

## UI 工具限制与停止点

浏览器自动化入口返回 `The browser access host is unavailable`。改用已初始化的 computer-use 窗口工具后，在新建的测试浏览器窗口中聚焦地址栏时，自动审批检查终止了本轮 Computer Use，原因为无法足够可靠地识别当前浏览器 URL。之后未继续 UI 操作，也没有通过其他工具绕过限制。

因此本轮无法验证浏览器真实显示 desktop_required，亦未进行桌面真实 IPC、刷新、关闭重启以及第二实例 busy 场景。下一轮须在 UI 工具可用时使用独立测试标识/临时应用数据完成这些检查；不能自动推进 Phase 2b 或其他业务。
